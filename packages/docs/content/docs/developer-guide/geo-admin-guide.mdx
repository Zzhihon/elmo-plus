本手册面向 GEO 工作台的平台管理员。所有设置都在 **工作台设置** 页，只有平台管理员能看到除“安全”以外的选项卡。

## 角色

| 角色 | 能做什么 |
| --- | --- |
| 平台管理员 | 成员角色、平台密钥、限额、保留期、审计、告警。**没有任何审核或发布权限** |
| GEO 运营 | 问法、采样、诊断、工单流转与发布登记、草稿与报告 |
| 技术审核人 | 审核产品参数、认证、案例等技术内容，可驳回并留言 |
| 市场审核人 | 审核对外表述，可驳回并留言 |
| 知识审核员 | 审核官网抽取的事实与客户资料 |
| 只读用户 | 查看看板、报告和工单状态 |

一个人可以同时拥有多个角色。组织的 owner 与 admin 自动是平台管理员；未分配角色的普通成员视为只读用户。API Key 最多拥有只读或运营权限，永远不能审核或管理。

## 成员与角色

为每位成员勾选或取消 GEO 角色。每次变更都写入审计日志，记录操作人和变更前后的摘要。

平台管理员如需审核内容，必须先给自己分配对应的审核角色。这一步同样留痕，所以不存在“管理员无痕绕过审批”的路径。高风险内容还要求审核人不是作者或责任人本人。

角色变更后，当前浏览器立即生效；其他已登录用户最长一分钟内生效。

## 审批（双人控制）

以下操作由一位平台管理员发起申请，必须由**另一位**平台管理员批准才会生效，申请人永远不能批准自己的申请：

- **启用 LLM 调用**（`llm_use_approved`）：批准前，语义评估只走规则并进入人工复核，AI 草稿功能提示未批准。
- **保留期变更**：见下文“保留期”。
- **关闭管理员 MFA 要求**。

申请需要填写理由，审批人可以批准或驳回并留言。待处理超过 48 小时会产生告警，7 天未处理自动过期。所有申请、批准、驳回和过期都写入审计日志。

**关闭 LLM 调用立即生效**，不需要第二人，同样写入审计。收紧权限的方向不设门槛。

只有一位平台管理员的部署无法完成双人审批，这是有意的：请至少为两人分配平台管理员。

## 平台密钥

平台密钥是采样目标等使用的第三方凭据，以组织为范围、用 `ELMO_ENCRYPTION_KEY` 加密保存在现有的 `secrets` 表中，不进入日志、工单或截图。

- 值只能写入，保存后**永远不再显示**。列表只展示引用名、最后更新时间、加密密钥编号，以及哪些采样目标在使用它。
- **轮换凭据**：输入新值并保存，约 60 秒内所有进程生效，旧值被覆盖。轮换写入审计日志，日志只记录引用名和操作人，不记录任何值。
- **轮换加密密钥**：把新密钥设为 `ELMO_ENCRYPTION_KEY`、旧密钥移到 `ELMO_ENCRYPTION_KEY_OLD` 并重启，然后点击 **用当前密钥重新加密**。完成后即可从环境中删除旧密钥。

非平台管理员调用密钥相关的页面或接口一律被拒绝，返回内容和日志中都不包含凭据。

## 限额与告警

位于 **限额、告警与保留期** 选项卡。


- **每日采样上限**、**单批次上限**、**成本预算**：留空表示不限，由采样模块在创建批次时校验。
- **告警接收人**：一组邮箱。只有配置了 `RESEND_API_KEY` 与 `RESEND_FROM_EMAIL` 时才发送邮件，否则告警只在工作台内展示，页面上会提示这一点。

这些设置由单个平台管理员修改，修改写入审计。

## 保留期

同样位于 **限额、告警与保留期** 选项卡，可以分别设置三类数据的保留天数：

| 类别 | 最短 | 删除的内容 |
| --- | --- | --- |
| 采样证据 | 30 天 | 过期的原始回答及其引用、评估、断言核对、工单证据关联，以及对应的对象文件 |
| 官网原始快照 | 30 天 | 过期的网页版本及其 HTML/解析文件 |
| 审计日志 | 180 天 | 过期的审计记录 |

- **留空表示永久保留，这是默认值，系统不会删除任何数据。**
- 变更需要双人审批。申请时页面给出预估：按新设置会删除多少行。
- 清理作业每天 03:40 UTC 运行，按依赖顺序删除数据库行，提交后再删除对应的对象存储文件。
- 仍被知识来源引用的网页版本，以及每个页面的最新版本，永远不会被删除，以保证已审核事实可以回溯到原文。
- 每一批删除都在同一事务内写一条汇总审计，记录类别、截止时间和数量。

## 审计日志

可按操作人、动作、实体类型、实体 ID 和时间范围查询。审计只保存变更前后内容的哈希，不保存值；元数据里名称像密钥、密码、令牌、凭据的字段会被替换为 `[REDACTED]`。审计日志本身不可修改，只能由保留期作业按设置删除。

## 运行状态

汇总近期的运行指标：

- 采样计划数、有效、失败、不可用；
- 各平台采样用时的 P50 / P95；
- 队列积压、重试次数、单次采样成本；
- 评估复核比例、报告生成成功率；
- 超时未处理的审批；
- 最近一次每日备份、迁移前备份和恢复演练的状态。

某个来源表还没有数据时显示“无数据”，不会显示为 0。下方列出未处理的告警，可以确认或关闭。

## 安全：两步验证

启用 GEO 工作台后，每位用户都可以在 **安全** 选项卡用验证器应用（TOTP）开启两步验证，并保存一次性备用码。工作台关闭时这项功能不出现，其他部署模式不受影响。

- 平台管理员在使用管理类设置前必须先开启两步验证，除非组织经双人审批关闭了该要求；重新开启要求由一位管理员即可完成，立即生效。
- 两步验证开启后，用邮箱密码登录时会多一步输入验证码或备用码。
- 只通过 SSO 登录的用户不受此限制：由身份提供方负责多因素认证，接入时请确认身份提供方已强制 MFA。

## 优化工单的流转

```
待分析 → 待指派 → 进行中 → 待技术审核 → 待市场审核 → 待发布 → 已发布 → 待复测 → 已验证
```

另有 **已驳回**、**已暂停**、**已取消**：

- 审核人驳回必须留言，工单回到“已驳回”，责任人修改后重新进入“进行中”。
- 暂停与取消必须写明原因；恢复后回到暂停前的状态。
- **高风险的官网改造**必须先填写上线审批编号、备份方案和回滚计划，才能进入“待发布”。
- 登记发布必须填写实际发布 URL、发布时间和可验证的证明。
- **“已发布”从不等于“有效”。** 只有关联了同一问法集的复测前、复测后两个采样批次（复测后批次必须在发布时间之后创建），工单才能标记为“已验证”。对比结果在工单详情中展示，样本量不足时会显著提示。
- 工单进入“待复测”后，worker 每小时把发布后首个完成的、同一问法集的采样批次关联为复测批次；是否“已验证”仍由运营人员查看对比后确认。
- 待技术审核或待市场审核超过 72 小时会产生告警。

工单的每一步都写入操作记录与审计日志，不可删除。
